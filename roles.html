How an aircraft becomes a role group

The role filter groups aircraft by what they are for. This page shows exactly how that mapping is made, for every one of the 185 type codes and 26 roles in the taxonomy. It is generated from the same configuration file the data pipeline reads, so it cannot describe anything the pipeline does not do.

Please correct this

This taxonomy was assembled with AI assistance, and the authors are very uncertain about it. Role assignments for military aircraft are a matter of doctrine, variant and operator, and a single type code frequently covers airframes doing quite different jobs. We expect errors here.

Corrections from subject-matter experts are actively wanted — ideally with a reference to public documentation we can cite, so the correction can be verified rather than simply believed. Send a correction.

How the assignment works

  1. The aircraft’s broadcast type code is stripped to letters and digits and upper-cased.
  2. That code is looked up in the designator table. There is no fallback and no guessing: a code that is not in the table yields no roles at all, rather than a default.
  3. If the designator has variant rules and the aircraft’s description matches one, the roles are narrowed to that rule’s list (see Variant narrowing).
  4. An aircraft matches a filter when its roles intersect the selected ones. Aircraft with several roles therefore appear under several groups — the roles are what the airframe could be doing, not a claim about a particular flight.

What this is not. A role is a property of the aircraft type, not an observation of the mission. Nothing here asserts what any individual flight was carrying or doing.

Excluded from the data entirely

Aircraft whose type could fill any of the roles below are dropped from the pipeline before anything else happens, so they appear in no map, count or export. The exclusion is deliberately conservative: if any role the type could fill is in this set, the aircraft is excluded.

If you are looking for helicopters and finding none, this is why — not an absence in the data.

When the role is unknown

Three synthetic buckets stand in when the lookup does not produce roles. They are not roles in the taxonomy; they exist so that an unresolved aircraft is visibly unresolved rather than silently dropped or lumped in with a real category.

typecode_unknown
The aircraft broadcast no type code at all, so there was nothing to look up.
type_unknown
A type code was broadcast but could not be resolved to a known aircraft type.
role_unknown
The type resolved fine, but its designator carries no roles in the taxonomy — so the aircraft is known and its job is not.

Variant narrowing

Some type codes cover a family of aircraft doing quite different jobs — a C-130 airframe may be a tanker, a gunship or a search-and-rescue platform. Where the aircraft’s description string identifies the variant, it narrows the roles to just those listed below, replacing the designator’s full set.

Order matters. Patterns are matched as substrings against the upper-cased description and the first match wins, so these are listed in taxonomy order, not alphabetically. If no pattern matches, the designator’s full role set applies.
